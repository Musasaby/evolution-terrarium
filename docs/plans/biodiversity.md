# 生物多様性を高める計画

作成日: 2026-10-12

## 目的

時間が経っても多くの種が共存し、種ごとに「食べ物・暮らす場所・得意な気温」が分かれた箱庭にする。
あわせて、既存 UI の文章量と画面占有率を減らし、3D 画面を広く見せる。

## 前提と制約

| 項目 | 決定 |
|---|---|
| 対象とする柱 | 生物のニッチ形質 / 地形の多様化 / 多様性の計測 / UI の簡素化 |
| 対象外 | 気候の局所化(場所ごとの天候・南北の気温勾配)。気温の場所差は今までどおり標高だけで生じる |
| 性能予算 | 1 ステップ平均の増加を **+5% 以内**(下記「性能の判定方法」) |
| 世界の広さ | `CFG.WORLD = 120` のまま。`MAX_POP` `MAX_PLANTS` も変えない |
| 剛体・当たり判定 | 1 個体あたりの剛体・当たり判定の数を増やさない。新しい物理オブジェクトを作らない |
| 神経回路 | `NI` `NO` を変えない(ゲノム長と計算量を据え置く) |

## 現状の分析

### 計測したベースライン(2026-10-12、`develop/multi-ai-agents-workflow` 589896f)

`npm run check:sim` 相当(seed 20261007、1500 ステップ):

```
1ステップ平均 9.14 ms
  環境 0.05 ms (1%) / 生物 1.36 ms (15%) / 物理 7.36 ms (80%) / 接触 0.37 ms (4%) / 集計 0.00 ms
生物 194 / 植物 2000 / 種 15
```

多様性の推移(18000 ステップ = 2 年、実効種数 = exp(シャノン指数)):

| seed | 0.3 年 | 1.0 年 | 2.0 年 | 2.0 年の現存種 |
|---|---|---|---|---|
| 1 | 11.50 | 7.16 | **3.19** | 11 |
| 2 | 10.95 | 8.79 | **3.86** | 11 |

現存種の数は保たれるが、個体の大半が 2〜3 種に偏っていく(少数の種が勝ち、残りは細々と残るだけ)。

### 多様性が落ちる原因

1. **全員が同じ資源を同じ効率で使う**: 草(センサーの植物)・木の葉(硬い植物)・肉(衝突ダメージ)を、どの個体も同じ `FOOD_GAIN` で得る。資源を分け合う理由がなく、運動性能で勝る種が全資源を取る(競争排除)
2. **耐える気温が全員同じ**: 寒さの費用は 5℃ 未満、暑さは 29℃ 超で一律。標高による気温差があっても、そこに特化する見返りがない
3. **水中は誰にとっても不利なだけ**: 湖は避けるべき場所でしかなく、ニッチにならない
4. **地形が単調**: 山 1 つ・湖 1 つ。植物の適地は気温と湿り気だけで決まり、場所ごとの資源の違いが小さい
5. **種分化が中立的な浮動頼み**: 種の判定は中立マーカーと体形の距離だけで、生態の違いが生殖隔離につながらない

### 性能面の見立て

物理が 8 割を占めるので、多様性は「物体を増やす」のではなく「同じ数の個体に違う暮らし方をさせる」ことで作る。
ニッチ形質は掛け算・比較が数回増えるだけで、物理コストはゼロ。地形・土壌の場は生成時や間引いた間隔で計算するので、毎ステップの負担はほぼない。

## 設計

### 1. 多様性の計測(最初に作る)

効果を数値で判定できるようにしてから、規則を変える。

- `src/sim/diversity.js`(新規・純粋関数): 生きている個体から次を計算する
  - 現存種数、実効種数 `exp(H)`(H = 種ごとの個体割合のシャノン指数)
  - 食性ニッチの実効数(各個体を最も効率の高い食べ物で 3 分類し、その exp(H))※ ニッチ形質の導入後に有効
  - 形質のばらつき(体積・体節数・好適気温・水棲度の標準偏差)
- `stats.js` の `recordStats` で `STATS` 間隔(80 ステップ)ごとに記録。O(個体数) なので負担は無視できる
- `tools/diversity-check.mjs`(新規)と `npm run check:diversity`: 複数シードを並行して長時間(既定 18000 ステップ)進め、年ごとの指標と区間ごとの所要時間を表にして出す

### 2. 地形の多様化

- **山と湖の数をシードで変える**: 山 1〜3 個(高さ・裾野の広さもばらつかせる)、湖 1〜3 個。尾根(既存の `ridge` ノイズ)で山どうしをつなぐ場合もある。山の多い世界は標高による気温差の幅が広がり、寒冷・温暖の住み分けが起きやすい
- **土壌の場** `terrain.soil`(格子 65×65、生成時にノイズで決める静的な値): 岩場 / 砂地 / 肥沃 / 泥炭 の 4 種
  - 植物種ごとに得意な土壌を持たせ、`suitability` に係数を掛ける(例: サボテン=砂地、針葉樹=岩場、広葉樹=肥沃、苔・葦=泥炭)
  - 結果として、同じ気温・湿り気でも場所ごとに生える植物が変わり、食べ物の種類が局所的に偏る
  - 計算は植物の更新(40 ステップごと)での表引き 1 回だけ
- **川(任意)**: 湖どうしや山から湖へ、湖面より低い細い水路を掘る。陸生の個体には障壁、水棲の個体には通り道になり、地理的隔離を生む。湖面は ±2.8m 変動するので、季節によって途切れたりつながったりする。効果が計測で確認できたときだけ採用する

### 3. 生物のニッチ形質

ゲノムに次の量的形質を追加する(`randomGenome` / `cloneGenome` / `recombine` / `mutate` すべてで扱う)。どれも「特化すると得意分野は強いが、他が弱い」交換関係を持たせる。

| 形質 | 範囲 | 効果 | 代償 |
|---|---|---|---|
| `diet`(3 要素: 草・木の葉・肉) | 各 0〜1、合計 1 に正規化 | 食べ物ごとの消化効率。`feed` で `FOOD_GAIN` に掛ける | 特化した方が得意な食べ物の効率の合計が高い(凸な交換関係)。ジェネラリストはどれも中程度 |
| `tOpt`(好適気温) | -10〜35℃ | 快適な気温帯の中心 | — |
| `tTol`(耐性の幅) | 2〜15℃ | 快適な気温帯の半幅。外れると寒さ/暑さの費用 | 幅が広いほど基礎代謝が増える |
| `aqua`(水棲度) | 0〜1 | 水中の費用と水中の減衰を下げる | 陸上の基礎代謝が増える |

関連する変更:

- **感覚**: 最寄りの植物を探すとき、距離を「自分の消化効率」で割った値で選ぶ(食べられない植物を追わない)。気温の入力を `(気温 - 15)/15` から `(気温 - tOpt)/15` に変え、「自分にとって寒いか暑いか」を感じさせる。どちらも入力の数は変えない
- **祖先と移入**: 創始集団ごとにニッチ形質をランダムに決める(集団内では少しだけばらつかせる)。初期の 14 種が最初から違う暮らし方を持つ
- **生態的種分化**: `geneDistance` にニッチ形質の差を小さな重みで加える。違う資源や気温に適応した集団ほど雑種が育ちにくくなる。重みは `CFG` に置き、計測で調整する
- **定数**: 交換関係の形・代償の係数は `CFG.NICHE`(新設)にまとめる

### 4. UI の簡素化

文章量と画面占有率を減らす。新しいパネルは作らない。

- **ヘッダー**: 副題 `EVOLUTION TERRARIUM` を削除。計器は単位と短いラベルで 1 行に収める(例: `2.3年 夏 18.4℃ 湖+0.3 晴 個体182 種11 世代34`)。操作ボタンは記号・短縮表記にし、説明は `title` 属性へ移す
- **操作ヒント** `#hint`: 常時表示をやめ、初回だけ数秒表示して消す(または `?` ボタンで表示)
- **右パネル**: 幅を 340px から縮める(目安 280px)。折りたたみボタン(とキー操作)で 3D 画面を全幅にできるようにし、状態を記憶する
- **統計タブ**: 凡例・見出しを短くし、「繁殖」の数値表は 2 列の小さな表にまとめる。多様性は新しいグラフを作らず「個体数と種数」のグラフに実効種数の線を足す
- **個体タブ**: 12 行の記録表を 2 列グリッドに詰める。ニッチ形質(食性の 3 本の帯、好適気温±幅、水棲度)を小さなバーで表示する
- **系統樹タブ**: 長い説明文を 1 行に縮め、詳細は `title` 属性(ホバー)へ移す
- **性能表示**: 初回の既定を非表示に変える(保存済みの設定があればそれに従う)
- **地形の色**: 土壌の種類を地面の色にわずかに反映する

## 性能の判定方法

物理の時間は個体数で大きく変わるため、合計時間だけでは規則の変更の負担を判定できない。次の 3 点で判定する。

1. `npm run check:sim`(1500 ステップ)で、**物理以外の区間(環境+生物+接触+集計)の合計の増加が 0.46 ms 以下**(ベースライン 1 ステップ平均 9.14 ms の 5%)
2. 1 個体あたりの剛体・当たり判定の数が変わらない(`physicsCounts()` ÷ 生物数で確認)
3. 世界の生成時間の増加が 10% 以内(地形・土壌の生成ぶん)

計測は同じマシンで 3 回行い中央値をとる。

## 成功基準

`npm run check:diversity`(seed 1, 2, 3、18000 ステップ = 2 年)で:

- 2 年時点の**実効種数の平均が 6 以上**(ベースライン 3.2〜3.9)
- 2 年時点の**食性ニッチの実効数の平均が 1.8 以上**(3 つの食性のうち 2 つ以上が実質的に使われている)
- 1〜2 年の間に「移入」による補充が起きないシードが過半(多様性が移入頼みでないこと)
- 上記「性能の判定方法」をすべて満たす

### グループ A: 計測

**A2. 長時間・複数シードの計測ツール**

- 受け入れ基準:

  - シードは子プロセスで並行実行する
  - この計画の「ベースライン」の表と同程度の値(seed 1 の 2 年時点で実効種数 3〜4)が再現される

### グループ B: 地形の多様化

**B1. 山と湖の数をシードで変える**
- 変更: `src/sim/terrain.js`(`generate`)
- 受け入れ基準:
  - `terrain.mtns`(1〜3 個)と `terrain.lakes`(1〜3 個)を持ち、seed 1〜10 で数の組み合わせが 3 通り以上現れる
  - どのシードでも陸地(初期の湖面より高い格子)の割合が 55〜85%
  - 外部から参照している `terrain.mtn` `terrain.lake` があれば新しい形に合わせる
  - 世界の生成時間の増加が 10% 以内

**B2. 土壌の場と植物の土壌適性**
- 依存: B1
- 変更: `src/sim/terrain.js`、`src/sim/plant-species.js`、`src/sim/environment.js`、`src/render/terrain-view.js`
- 受け入れ基準:
  - `terrain.soilAt(x, z)` が 0〜3(岩場・砂地・肥沃・泥炭)を返し、陸地で 4 種すべてが 5% 以上を占める
  - 各植物種に `soil`(4 要素の係数)があり、`suitability` に掛かる
  - seed 1 で 1500 ステップ後、少なくとも 2 種の植物について「最も多い土壌」が異なる
  - 地形の色に土壌が反映される(ブラウザ確認。できない場合はその旨を報告)

**B3. 川(任意)**
- 依存: B1
- 変更: `src/sim/terrain.js`
- 受け入れ基準:
  - 湖が 2 つ以上ある世界で、湖どうしをつなぐ幅 1〜2 格子・湖面より低い水路ができる
  - 侵食で 1 年以内に埋まらない(1 年後も水路の 70% 以上が湖面より低い)
  - C5 の計測で、川あり・なしの実効種数を比較して報告する(改善がなければ既定で無効にする)

### グループ C: 生物のニッチ形質

**C1. ゲノムにニッチ形質を追加**
- 変更: `src/sim/genetics.js`、`src/sim/config.js`(`CFG.NICHE`)、`src/sim/creatures.js`(創始集団)
- 受け入れ基準:
  - `diet` `tOpt` `tTol` `aqua` が `randomGenome` で生成され、`cloneGenome` で複製、`recombine` で両親の中間を中心にばらつき、`mutate` で変異する(範囲は設計の表どおりにクランプ)
  - 創始集団の個体は同じニッチ形質を中心に小さくばらつく
  - この時点では形質は効果を持たない(ハッシュは変わってよい)

**C2. 食性による消化効率**
- 依存: C1
- 変更: `src/sim/interactions.js`、`src/sim/creatures.js`(`sense`)
- 受け入れ基準:
  - `graze` `browse` `applyHit`(肉・死骸)で、得られるエネルギーに `diet` から決まる効率が掛かる
  - 効率の関数は、特化した個体の得意な食べ物の効率が、ジェネラリストのどの効率よりも高い
  - 植物の探索で、自分が消化できない種類の植物(効率が閾値未満)を最寄りとして選ばない
  - 単体テスト相当の確認スクリプト(`tools/` 内、または A2 のツールのオプション)で、草専門・肉専門・ジェネラリストの効率の値を表示できる

**C3. 耐温性**
- 依存: C1
- 変更: `src/sim/creatures.js`(`updateCreatures` の寒暖の費用、`sense` の気温入力)
- 受け入れ基準:
  - 快適帯 `[tOpt - tTol, tOpt + tTol]` の外で寒さ・暑さの費用がかかり、`tTol` に比例して基礎代謝が増える
  - 気温の感覚入力が `(気温 - tOpt) / 15` になる
  - 個体パネルの「寒暖」の費用表示がそのまま使える(`c.cost.climate` に入る)

**C4. 水棲適応**
- 依存: C1
- 変更: `src/sim/creatures.js`
- 受け入れ基準:
  - 水中の費用が `aqua` に応じて下がり(最大 80% 減)、水中での減衰も下がる
  - `aqua` に応じて陸上の基礎代謝が増える
  - 剛体・当たり判定の数は変わらない

**C5. 生態的種分化と調整**

## リスクと対策

| リスク | 対策 |
|---|---|
| 特化した種が季節の資源不足で一斉に絶滅し、かえって多様性が下がる | 交換関係の形(どこまで特化を有利にするか)を `CFG.NICHE` で調整。移入回数を指標に入れて監視 |
| 肉食の効率が高すぎて個体数が崩壊する | 肉の効率の上限を草・木より低めに始め、C5 で調整 |
| 耐性の幅を広げるのが常に得になり、全員ジェネラリストに収束する | 幅の代償(基礎代謝)を計測しながら調整。`traitSd` の推移で収束を検知 |
| 多様な地形で生成直後に湖へ落ちる・山頂に孤立する創始集団が増える | 既存の創始集団の配置条件(水上・高地を避ける)を、自分の `tOpt` に合う標高を選ぶ形に広げる |
| 長時間の計測が遅い(1 シード 18000 ステップ ≈ 3 分) | シードを並行実行。調整中は 9000 ステップ・2 シードに縮めてよい |
