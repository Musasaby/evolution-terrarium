2. 原因の図

湖: 沈んで、急な岸を登れない(#34)

深さは縁の高さの 2.2〜3.0 倍、形は exp(−(d/r)³)。水中で変わるのは減衰と費用だけ。

A 浮力 + B 遠浅の岸を先に入れる。足りなければ C「陸の方向」の感覚、D 浅瀬での祖先の試走。

seed 1 と 2 の合計。seed 2 は上陸 0 回。水中に長くいた個体の水棲度は平均と変わらず、適応して住んでいるのではなく出られないだけ。

山: 麓から上に行かない(#35)

祖先の試走は平らな床だけで、坂の感覚 slope は 0 に固定。山の上は寒さの費用が増えるだけで、得がない。移動の速さの中央値は 0.2〜0.4 m/秒(一辺 120 m の世界)。

体節: 増やすと損だけが増える(#38)

画面では平均の体節数が 6 年目に約 4 から約 5.5 へ上がり、12 年目まで横ばい。時間を延ばすだけでは増えない。体節の得を作り、費用と繁殖の壁を見直す。重さは「体節の合計で個体数の上限を決める」などで抑える。

シミュレーションと UI は互いに依存しないので、2 本の列で進められる。シミュレーションの列は前の段の結果を使うので、上から順に行う。

sim の列は振る舞いを変えるので、各段で npm run check:diversity と群島の多様性の計測をやり直す。UI の列は sim を変えないので、状態ハッシュが変わらないことを確かめる。

4. 確かめ方

sim の列

  • 入水と上陸の回数、標高の帯ごとの個体数、移動の速さ、体節数の分布を、同じ計測で前後比較する
  • npm run check:diversity(3 年・3 シード)で、個体数と実効種数が悪くならない
  • 群島は node tools/archipelago-diversity.mjs で確認する
  • 性能は docs/plans/biodiversity.md の「性能の判定方法」を満たす。体節が増えても物理の負荷を抑える

UI の列

  • ブラウザで、島 1 つの世界と群島の両方を確認する(ヘッドレスでは確認できない)
  • 10 年以上動かした状態で、グラフと系統樹の直近の変化が読み取れる
  • 幅 900 px 前後でも、ヘッダーのボタンが 3 段に折り返さない
  • 絵文字を使っていない
